## Codebase Patterns
- bd formulas use TOML format with `.formula.toml` extension (not YAML); search path is `<checkout-root>/.beads/formulas/`
- `bd mol wisp` creates only the root issue (1 issue); use `bd mol pour` to materialize all 5 phase beads as separate issues
- `bd list --json --all` returns a flat array; each issue has `dependencies[]` with `type: "blocks"` for sequential deps and `type: "parent-child"` for hierarchy
- `bd cook <formula>` requires an active bd database; use full file path (`bd cook /abs/path/to.formula.toml`) from a `bd init`-ed directory
- `bd cook --dry-run` validates formula structure without writing to the database
- dolt uses `dolt version` (not `dolt --version`) — the `--version` flag is invalid for dolt
- bd (beads) installed via `CGO_ENABLED=0 go install github.com/steveyegge/beads/cmd/bd@latest`; binary lands in ~/go/bin — symlink to ~/.local/bin for PATH availability
- bd requires CGO build (`go install` without CGO_ENABLED=0) for embedded Dolt mode; CGO_ENABLED=0 build requires `bd init --server` with an external dolt sql-server running
- dolt file remotes use `file:///absolute/path` URL format; bare paths are treated as DoltHub remote names and cause push failures
- BEADS_REMOTE_PATH is stored as a `file://` URL (e.g. `file:///home/user/project/.beads-remote`), not a bare path
- dolt requires user identity (`dolt config --global --add user.email/user.name`) before `dolt init` works; it does NOT fall back to git global config
- SQLAlchemy identity map + `expire_on_commit=False`: when a test session creates an object, commits it, then an HTTP call (different session) mutates it, the test session returns the stale cached object unless you call `session.expire(obj)` before re-querying
- `_ensure_git_repo` in worktree.py runs git init BEFORE the `try/except SubprocessError` block — tests that mock subprocess.run must pre-create `.git/` in the tmp dir to skip it (otherwise the first captured call is `git init`, not `git worktree add`)
- AppConfig uses `max_agents_per_type` (dict, per-agent) not `max_agents_per_column` (removed scalar)
- `bd create <title> --parent <parent-id>` creates a child bead; parent cannot be closed until all children are closed (bd enforces this — use `--force` to override, but don't)
- When filtering bd list output for child beads, filter by title (e.g., "resolve-conflict" in title) rather than dependency type — the `parent-child` dep type appears on BOTH parent and child objects, so filtering by it catches the parent too
